# 悬浮网址盒 Mac M 系列版方案

日期：2026-10-08。状态：用户已批准方案，尚未实现或完成 Mac 实机验收。

## 目标和交付

让使用 M 系列芯片 Mac 的人，获得与现有 Windows 版相近的桌面网址入口，不需要安装 Python。交付 arm64 的 FloatingLinkDock.app、可分享 ZIP 和简明 Mac 使用说明。首版面向 macOS 13 或更高版本；实际最低版本必须以构建依赖和实机验证结果为准，不能仅凭打包配置宣称兼容。

## 已确认的使用方式

- 保留浅绿色背景、紧凑网站方块、添加编辑删除及自由拖动。
- 每次正常启动展开；点击笑脸或减号收起，单击小笑脸展开。
- 顶部菜单栏保留笑脸入口：显示网址、重置位置、退出。不显示 Dock 图标。
- 单击网站使用系统默认浏览器；右键可选择检测到的 Safari、Chrome、Edge、Firefox，只影响本次打开。
- 保留置顶、屏幕边缘吸附及可选半隐藏；不得遮挡菜单栏或不可恢复地移出可见屏幕。
- 自动保存网址和布局；开机启动默认关闭，只有用户主动勾选才修改个人启动配置。
- Windows 版行为、已有数据格式和当前用户文件保持不变。

## 技术路线

采用已获同意的“复用现有 Python 界面、增加平台适配”方案。完整原生重写会增加重新实现与回归范围；网页版不能满足独立桌面悬浮和菜单栏入口，均不作为首版方案。

### 平台边界

新增平台选择入口，界面、启动流程和方块菜单不再直接导入 Windows 模块。保留 windows_integration.py；新增 macOS 适配，实现统一的浏览器、工作区域、启动管理、单实例和错误展示接口。Mac 导入和启动不应触及 winreg、windll 或 Windows 专属窗口属性。

Mac 字体改为可用系统字体。窗口坐标、缩放与多屏工作区域统一到 Tk 坐标；重点验证 Retina、负坐标显示器和上下排列显示器，不直接混用 Cocoa 底部原点与 Tk 顶部原点。

### 菜单栏和事件循环

使用 macOS Cocoa 能力支持菜单栏入口与不显示 Dock 的应用模式。优先验证现有 pystray 的 Mac 后端与 Tk 主线程共存；菜单动作通过现有命令队列交回 Tk，禁止后台线程直接修改控件。

此集成尚未在 Mac 上验证。若两种事件循环无法可靠共存，改用 PyObjC 原生状态栏适配，保持相同队列接口；如果需要进一步改成完整原生 UI，先说明范围变化并获得用户同意。

### 浏览器

检测系统与用户 Applications 目录内的目标应用；优先用应用路径而非猜测可执行文件路径打开指定浏览器。URL 复用现有校验，仅允许 HTTP/HTTPS。启动参数使用数组，不拼接 shell 命令，不更改默认浏览器。

浏览器未安装、已移除或打开失败时给出中文提示，保留默认浏览器选项。只承诺常规安装的四种浏览器，不承诺任意自定义安装位置都能发现。

### 数据与错误

Mac 保存到用户目录下 Library/Application Support/FloatingLinkDock，与 Windows 数据目录隔离。继续使用 version=1 的 JSON、原子写入、损坏备份和日志轮换。新安装不自动携带开发者或 Windows 用户的私人网址。

启动失败也应显示 Mac 可读的错误提示，不能再次依赖 Windows MessageBox。网址文件不打印到构建日志、测试输出或分享包。

### 启动与单实例

只管理本应用拥有的用户级启动条目；可关闭，不修改系统级配置。移到 Applications 后再启用开机启动。重复打开不能产生多个菜单栏图标或窗口，并应让现有窗口重新显示。退出后释放锁；崩溃遗留文件不能永久阻止再次启动。

## 构建和发布边界

使用 Apple Silicon macOS 环境构建 arm64 应用，打包 Mac 后端、Cocoa 依赖和图标。当前 Windows 环境可准备适配源码、打包配置和非实机测试，不能据此声称已经交付可用 Mac 程序。

构建环境尚未确定。先检查是否有用户授权且可用的 Mac 执行环境；没有时交付构建材料并明确缺少 Mac 构建与实机验证，不擅自创建云资源或发布 GitHub 工作流。

首版不默认使用或购买 Apple Developer 凭据。可在构建机做本地临时签名，但不得将其说成正式开发者签名或 Apple 公证。对外免警告分发需要后续具备证书、公证条件并单独授权。使用说明不得建议全局关闭系统安全检查。
