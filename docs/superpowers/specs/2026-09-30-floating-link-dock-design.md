# 桌面悬浮网址盒设计说明

日期：2026-09-30  
平台：Windows 10 / Windows 11  
交付物：Python 源码与可独立运行的 Windows EXE

## 1. 目标

制作一个始终可见、占用空间很小的桌面悬浮网址盒。用户可以把常用网站保存在其中，通过单击悬浮按钮展开列表，再单击目标网站用系统默认浏览器打开。

成功标准：

- 收起时不明显遮挡桌面或其他应用。
- 展开、收起和打开网址的路径足够直接。
- 用户能够添加、编辑、删除和调整网址顺序。
- 网址与设置在程序重启后保留。
- 源码可继续修改，EXE 可在未安装 Python 的 Windows 电脑上运行。

## 2. 范围

### 包含

- 可拖动、无边框、始终置顶的悬浮窗口。
- 收起与展开两种窗口状态。
- 单列表网址管理。
- 网址的添加、编辑、删除和上下排序。
- 使用默认浏览器打开网址。
- 本地 JSON 数据持久化。
- 保持置顶和开机启动设置。
- 单实例保护。
- Windows 高 DPI 支持。
- Python 源码、依赖文件、运行脚本、打包脚本和独立 EXE。

### 不包含

- 账号、云同步或多设备同步。
- 网址分组、标签和搜索。
- 内置浏览器。
- 在线服务或后台服务器。
- 自动抓取复杂网站元数据。

## 3. 技术方案

应用使用 Python 和 CustomTkinter 构建界面，并通过 PyInstaller 打包为 Windows EXE。

选择该方案的原因：

- Python 源码易于维护和二次修改。
- CustomTkinter 能提供比原生 Tkinter 更现代的外观，同时保持应用轻量。
- PyInstaller 可以生成不依赖本机 Python 环境的可执行文件。
- 所有数据均保存在本机，无需网络服务。

程序拆分为以下职责单一的模块：

| 模块 | 职责 |
|---|---|
| 应用入口 | 初始化高 DPI、单实例保护、数据目录与主窗口 |
| 悬浮窗口 | 管理收起、展开、拖动、置顶和屏幕边缘约束 |
| 网址列表 | 渲染网址项并处理打开、编辑、删除和排序操作 |
| 编辑表单 | 收集名称与网址，完成规范化和校验 |
| 数据存储 | 安全读取和原子写入 JSON，恢复损坏数据 |
| 系统集成 | 调用默认浏览器并管理当前用户的开机启动项 |
| 设置与状态 | 保存窗口位置、置顶偏好、开机启动偏好和首次运行状态 |

## 4. 交互设计

### 收起状态

- 窗口约为 52 × 52 像素，显示网址盒图标。
- 单击按钮展开面板。
- 按住并拖动可移动窗口。
- 窗口位置在拖动结束后保存。
- 右键打开设置菜单，包含保持置顶、开机启动和退出。

为避免拖动与单击冲突，移动距离超过系统阈值时视为拖动，否则视为单击。

### 展开状态

- 面板从悬浮按钮下方展开；下方空间不足时改为向上展开。
- 窗口自动保持在当前显示器的可用工作区域内。
- 顶部显示标题、添加按钮和收起按钮。
- 中部显示网址列表；超过可视高度后滚动。
- 每个网址项显示名称和域名。鼠标悬停时显示上移、下移、编辑和删除操作。
- 单击网址项的主体区域后，使用系统默认浏览器打开。
- 删除前显示确认对话框。

### 添加与编辑

- 表单直接在展开面板内显示，避免额外的复杂窗口。
- 字段为“名称”和“网址”。
- 输入 `example.com` 时自动规范化为 `https://example.com`。
- 名称留空时使用网址域名作为名称。
- 校验失败时在对应字段附近显示可操作的错误说明，并保留用户输入。

### 首次运行

- 默认提供 3 个可删除的示例网址。
- 示例数据仅在首次运行且没有现有数据时创建。
- 空列表显示空状态和“添加第一个网址”按钮。

## 5. 视觉设计

- 视觉语言接近 Windows Fluent 的轻量桌面工具。
- 采用统一的深色石墨灰主题，不在不同区域切换明暗主题。
- 薄荷青作为唯一强调色，用于焦点、主要操作和活动状态。
- 使用统一的中等圆角、克制阴影和清晰边界。
- 不使用装饰性渐变、无意义徽章或多余状态点。
- 展开和收起采用短时状态过渡；动画只用于表达窗口状态变化。
- 检测系统减少动画偏好；启用时关闭非必要过渡。
- 文本、图标、输入框和焦点状态满足清晰可辨的对比度要求。

## 6. 数据设计

用户数据保存在当前用户的本地应用数据目录，而不是 EXE 所在目录，以兼容 Program Files 等不可写安装位置。

建议目录：

```text
%LOCALAPPDATA%/FloatingLinkDock/
  links.json
  settings.json
  backups/
```

网址记录包含稳定标识、名称、规范化网址和排序序号：

```json
{
  "version": 1,
  "links": [
    {
      "id": "本地生成的唯一标识",
      "name": "示例网站",
      "url": "https://example.com",
      "order": 0
    }
  ]
}
```

设置记录包含窗口坐标、保持置顶、开机启动和首次运行状态。数据文件不保存密码、Cookie 或浏览器凭据。

## 7. 保存与恢复

- 保存时先将完整内容写入同目录临时文件并刷新到磁盘，再原子替换正式文件。
- 读取时校验 JSON 结构、版本与必要字段。
- 如果文件损坏，将原文件复制到 `backups` 目录并使用时间戳命名，然后恢复为空列表。
- 数据恢复时在界面中显示简短提示，并保留备份位置供排查。
- 排序、编辑和删除只有在保存成功后才更新最终界面状态；保存失败时恢复旧状态并提示原因。

## 8. 系统行为

### 默认浏览器

网址通过 Windows 默认浏览器打开。打开失败时显示错误提示，不阻塞悬浮窗口的其他操作。

### 开机启动

开机启动只作用于当前 Windows 用户。设置关闭时移除由本程序创建的启动项，不影响其他项目。源码运行和 EXE 运行分别解析正确的程序路径。

### 单实例

程序启动时使用仅限当前用户的实例锁。检测到已有实例时，新进程退出，并请求已有窗口显示在前台。

### 多显示器与高 DPI

- 启动时启用 Windows DPI 感知。
- 保存窗口位置时记录逻辑位置。
- 显示器布局变化或原显示器不可用时，将窗口修正到主显示器可用区域。
- 展开方向根据当前显示器剩余空间动态选择。

## 9. 错误处理

| 情况 | 行为 |
|---|---|
| 网址为空或格式无效 | 在表单内提示，不保存 |
| 数据目录无法创建 | 显示明确错误并以只读模式启动 |
| 数据保存失败 | 保留旧数据并提示用户 |
| JSON 文件损坏 | 备份损坏文件，恢复空列表并提示 |
| 浏览器启动失败 | 显示错误，应用继续运行 |
| 开机启动设置失败 | 设置回滚并显示原因 |
| 重复启动 | 激活已有窗口并退出新进程 |
| 保存的窗口位置不可见 | 自动移回主显示器工作区域 |

## 10. 测试与验收

### 自动测试

- 网址规范化与校验。
- 名称自动生成。
- 列表添加、编辑、删除和排序。
- JSON 序列化、原子保存和损坏文件恢复。
- 设置读写与默认值。
- 屏幕边缘位置修正与展开方向计算。

### Windows 手动验收

- 悬浮窗口可拖动并在重启后恢复位置。
- 单击能稳定展开和收起，拖动不会误触发单击。
- 展开面板不会超出屏幕工作区域。
- 网址增删改排序后重启程序，结果保持一致。
- 点击网址可由默认浏览器打开。
- 保持置顶开关即时生效。
- 开机启动可开启、关闭且不会重复创建。
- 第二次启动不会产生另一个悬浮窗。
- 100%、125%、150% 和 200% 缩放下界面可用。
- EXE 在未安装 Python 的 Windows 环境中能独立运行。

只有在自动测试通过、Windows 手动验收完成、独立 EXE 成功启动，并确认源码与 EXE 使用同一数据格式后，项目才视为完成。
